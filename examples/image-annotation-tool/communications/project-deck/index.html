1 · What it is

Images go in, reviewed bounding boxes come out

An admin uploads a batch of images. Each image becomes exactly one task, which is annotated, reviewed and, once approved, exported as COCO-style JSON.

  • task the unit of work: one per image, carries the status
  • annotation one labelled box, in pixels of the original image
  • review one approve or reject decision, kept as history
  • export one run that writes all approved boxes to a file

The work happens in two places:

While you wait · api

A FastAPI service handles login, uploads, the task lifecycle, boxes and reviews.

In the background · worker

An RQ worker makes a thumbnail per image and builds the COCO export file.

3 · How it works

One image, from upload to export

  • upload: stores the original in MinIO and creates one pending task
  • claim: the oldest pending task goes to the annotator who asks
  • draw + submit: boxes are saved as a whole set; at least one is needed
  • review: approve ends the task; reject needs a comment
  • export: all approved tasks, written as one COCO JSON file
  • background jobs: queued in Redis, run by the worker

Lifecycle: approved is final. Arrow colour shows which role makes the move.

Four of the six tables; users and exports are left out here.

A task that is rejected and resubmitted has several rows in reviews; that table is the history. width, height and thumbnail_key on images stay null until the worker has run. An export has its own, simpler status: queued, running, then done or failed.

3 · How it works

Uploads pass through the api; downloads go straight to MinIO

→ steps: upload · the signed URL · the direct download

  • Upload: the api reads each file and puts it in bucket images
  • Signing: every task and export response carries URLs valid for one hour
  • Two endpoints: S3_ENDPOINT inside the network, S3_PUBLIC_ENDPOINT for the browser
  • Download: images, thumbnails and the export file never pass through the api
api/app/storage.py upload_image, presigned_url.env.example S3_ENDPOINT, S3_PUBLIC_ENDPOINT
One hour is the default expires_in=3600 of presigned_url. URLs are signed against the public endpoint because the browser, not the api, fetches the objects. nginx accepts request bodies up to 200 MB for uploads (web/nginx.conf).
Flow 1 · upload a batch

The api answers at once; thumbnails are made afterwards

→ steps through each message

api/app/routes/images.py upload_batchapi/app/queue.py enqueue_thumbnailworker/jobs/thumbnail.py generate_thumbnail
Messages 3 and 4 repeat per file; there is one commit for the whole batch, then one job per image. Tasks are claimable as soon as the request returns. The review queue shows a thumbnail only once the job has run; the page tolerates a missing one.
Flow 2 · export approved annotations

Request an export, poll for it, download the file

→ steps through each message

api/app/routes/export.pyworker/jobs/export_coco.py export_approvedweb/src/pages/AdminUploadPage.tsx polling
If the job raises, the worker sets the export to failed and the page stops polling. The job timeout is 600 seconds (api/app/queue.py). Category ids in the COCO file are assigned per distinct label, in order of first appearance.
