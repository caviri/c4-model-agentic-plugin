Read any codebase
like a map.

One command explores your repository and writes two pages: an interactive architecture map you can open from the system down to the code, and a slide deck that explains it. Every box points to a file.

Open the live map → Read the docs

How it works

From repository to map in four moves

  1. 01

    Explore

    Claude reads from the outside in: README, deployment files, manifests, entrypoints, then the main flows.

    README.mddocker-compose.ymlpyproject.toml

  2. 02

    Ask

    A few questions, each with a default: who will read it, what is in scope, which flows matter. Then you correct its summary.

    audience?scope?flows?

  3. 03

    Brief

    It writes the brief: actors, containers, components, relationships, flows and state machines, each with the file it came from.

    project-brief.md

  4. 04

    Generate

    It builds the map and the deck, opens both in a headless browser, and reads the screenshots before it reports back.

    architecture-explorer/index.htmlproject-deck/index.html

The map

Everything a map of your code should do

Four levels, one page

System context, containers, components, code. Boxes open in place, and arrows reattach to whatever is visible.

Scenarios that play

Each runtime flow as a collaboration diagram, a sequence diagram or a table, at any level. Step through it or press play.

A sequence inside any box

Open a container and press ⇅: its parts become lifelines and the scenario draws itself in place, on the map.

State machines

Lifecycles drawn as states and transitions inside the box that owns them, with initial and final states marked.

Grounded in the code

Every box carries its file and line, linked to the repository. The build checks that each path exists before it calls the page done.

An RDF graph, too

Download the architecture as Turtle, JSON-LD or a single-file .rete graph and query it with SPARQL. No server needed.

Edit it in the browser

Press ✎ edit: drag boxes in from a palette, move them, Alt+drag to connect, change any field or scenario step. Undo, then download the new model or the page.

Export any diagram

The whole map, the pinned board or a scenario diagram as an SVG, a PNG or a page of its own, in the colours on screen.

Your colours, your sizes

Six colour themes (or follow the system), and a size menu for the interface, the spacing between boxes and the labels and arrows.

And a deck

Slides that explain it to the next developer

  • C4 slides that zoom into each other, from context to components
  • Step-through and sequence diagrams, drawn as SVG and checked for overlaps
  • Code with line-by-line highlighting, and a where label pointing at the file
  • Speaker notes, a reading view, light and dark

And its history

See how the architecture changed, and who changed it

  • Every merge, release or pull request that touched the model becomes a version on a timeline in the explorer
  • Compare any two: added boxes and arrows in green, removed ones as red ghosts, changes in amber, each with its author and commit
  • Diff reports for two branches or a pull request, and blame for every box
  • An RDF 1.2 dataset with PROV-O provenance: a named graph per version, a reifier per changed triple

Background

Built on Simon Brown’s C4 model

The four levels this plugin draws (system context, containers, components and code) are the C4 model, created by Simon Brown. It grew out of the software architecture workshops he ran from the mid-2000s, when attendees could not make sense of the diagrams they were drawing; the name “C4” first appeared in his QCon London workshop in March 2011.

This plugin is an independent project, not affiliated with or endorsed by Simon Brown. It uses the C4 levels as its map. For the model itself, go to the source.

  • Websitec4model.com The official site of the C4 model: the abstractions, the diagram types, notation, FAQ and history.
  • Talk · videoVisualising software architecture with the C4 model Simon Brown at Agile on the Beach, July 2019. The best single introduction.
  • BookThe C4 model Simon Brown’s book on the model, on O’Reilly.
  • Authorsimonbrown.je Simon Brown’s site, with his talks, writing and C4 workshops.
