A Claude Code plugin · C4 model

Read any codebase
like a map.

One command explores your repository and writes two pages: an interactive architecture map you can open from the system down to the code, and a slide deck that explains it. Every box points to a file.

Open the live map → Read the docs

How it works

From repository to map in four moves

  1. 01

    Explore

    Claude reads from the outside in: README, deployment files, manifests, entrypoints, then the main flows.

    README.mddocker-compose.ymlpyproject.toml

  2. 02

    Ask

    A few questions, each with a default: who will read it, what is in scope, which flows matter. Then you correct its summary.

    audience?scope?flows?

  3. 03

    Brief

    It writes the brief: actors, containers, components, relationships, flows and state machines, each with the file it came from.

    project-brief.md

  4. 04

    Generate

    It builds the map and the deck, opens both in a headless browser, and reads the screenshots before it reports back.

    architecture-explorer/index.htmlproject-deck/index.html

About the example

The map

Everything a map of your code should do

Four levels, one page

System context, containers, components, code. Boxes open in place, and arrows reattach to whatever is visible.

Scenarios that play

Each runtime flow as a collaboration diagram, a sequence diagram or a table, at any level. Step through it or press play.

A sequence inside any box

Open a container and press ⇅: its parts become lifelines and the scenario draws itself in place, on the map.

State machines

Lifecycles drawn as states and transitions inside the box that owns them, with initial and final states marked.

Grounded in the code

Every box carries its file and line, linked to the repository. The build checks that each path exists before it calls the page done.

An RDF graph, too

Download the architecture as JSON-LD or a single-file .rete graph and query it with SPARQL. No server needed.

And a deck

Slides that explain it to the next developer

  • C4 slides that zoom into each other, from context to components
  • Step-through and sequence diagrams, drawn as SVG and checked for overlaps
  • Code with line-by-line highlighting, and a where label pointing at the file
  • Speaker notes, a reading view, light and dark

Evidence over plausibility

Every container, arrow and flow step cites a file. What it had to infer is marked as inferred.

Your vocabulary

Things are named the way your code and your team name them, not the way a textbook would.

Checked before it is done

Schema, paths, line numbers and layout are checked by script; the pages are opened and looked at.

Install

Map your codebase this afternoon

Needs Claude Code. Python 3 builds the deck; Node.js 18+ and Chrome or Edge are optional, for building and checking the map.
